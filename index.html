Operator · a macOS app for Claude Code

You run the agents.

Operator makes the work visible and steerable: every tool call, diff, and delegation on one live board, each task sealed in its own git worktree, nothing leaving your machine. Below is the actual app, rebuilt at true scale in the browser, one view per feature.

Finding your way

Operator is project-first. You land on your projects, pick one, and the whole window scopes to it: its lanes, its sessions, its channel. Nothing from anywhere else is in the way.

01

The project gallery

the launcher

Cards for what is active, one-line rows for what you have shelved. A shelved project recedes structurally rather than by being dimmed, and the filter still searches both shelves so nothing becomes unfindable.

Active is a decision (archivedAt), not a measurement. Recency could not carry it: lastActiveAt tracks when a project last did work, not when you looked at it, so a derived split would reshuffle itself between restarts. The orb strip appears only when something is genuinely running.

  • givesNineteen projects stay legible, and the ones at rest get out of the way.
  • costsShelving is manual. Nothing gets filed away without you.
02

Project rail and scoped sidebar

one project in view

A persistent rail carries your open projects as colour and acronym tiles with a corner status pip. It owns navigation, so the sidebar header is identity only and the list below it is just this project: its lanes, and the sessions running in them.

Scope is durable. It survives opening preferences, usage, or another view, and focusing a session sets it, so you cannot end up looking at one project while acting on another.

  • givesPeripheral awareness of every open project, at no vertical cost.
  • costs38px of width, always. Names live in the hover card.

Watching

An agent that works out of sight is an agent you have to trust blindly. These three views exist so you never have to: the call tree as it happens, the reasoning as it streams, and the terminal underneath it all, still yours to take over.

03

Orchestration timeline

nothing to install

Nested tool calls, subagent delegations, durations ticking as they run. The in-flight row carries the accent border; what is queued behind it stays on screen instead of appearing only once it starts.

Operator rebuilds this from Claude Code's own transcript files, so there is nothing to install into your sessions and nothing to keep in sync. The tailer polls once a second, which is why durations tick rather than stream.

  • givesThe whole call tree, live, without instrumenting anything.
  • costsAbout a second of lag. Phase is the honest signal, not keystrokes.
04

Structured transcript and plan

tool calls as blocks

The transcript records what the agent did, not only what it said. Tool calls are first-class blocks, and consecutive calls of the same kind coalesce into one line, so a two-hundred-turn session reads as prose with punctuation between it rather than a wall of cards. A delegated run carries the subagent that made it.

The status line says what is happening in words ("Editing", "Running a command", "Delegating"), because the tool name is jargon at the foot of a reading surface. While the agent works, send becomes Stop. Beside it the agent's own plan ticks off by glyph and colour only: ✓ done, ▸ in flight, ○ not started.

  • givesA record you can audit, and one control that stops the run.
  • costsTool output is capped when stored. Large results are truncated, not lost.
05

Terminal and concurrent sessions

a real pty

Every session is a real pty you can type into, with its own reserved dev-server port. Take over mid-task, run a command yourself, hand it back.

The four phases are running, waiting on you, idle, and compacting, taken straight from the app's own session types. There is no presence or typing indicator, because a poller cannot honestly provide one.

  • givesA terminal you can seize at any moment, not a read-only log.
  • costsOne pty per session. These are real processes with real memory.

Directing

Configuration is the tax you pay every time you start an agent. Operator makes you pay it once: lanes that already know their model and permissions, a queue that feeds them, and a room where they say what they found. Lanes should talk. They should not be able to commission each other's work without you.

06

Roster and task queue

one click to launch

Staff the project once. Each lane pins a model, an effort level, and permissions, so starting a correctly configured session is one click rather than a setup ritual you half remember.

Only working lanes get a full row; the rest collapse under Ready, one line each and still one click from launching. Queue tasks against that roster and they dispatch, run, and come back as a diff. A task whose lane disappeared is marked abandoned, not done: the run ended, but nobody saw the work finish, and calling that "done" is the kind of lie every count downstream repeats.

  • givesBacklog to running to reviewable, without babysitting the handoffs.
  • costsA queued task waits its turn. A busy lane reads it when its current task ends.
07

The project channel

read-only for now

Every project gets a room. Lanes post to it when something changed: a task finished, a lane is blocked, or one of them found something that affects another's work. Each line carries an author, a target, and its delivery state.

That state is the whole design. A lane that is not the coordinator cannot silently commission work: its dispatch is held until you approve it. A message to a busy lane is queued and read when its current task ends. Saying so on screen is the difference between honest and broken.

  • givesOne place to see what your agents told each other, with a gate on the ones commissioning work.
  • costsYou cannot post yet. The feed and the approval gate ship first; sending follows.
08

Agent library

your .claude/agents

A visual editor over the .claude/agents files you already have. Haiku for extraction, Sonnet for the everyday, Opus where it earns its keep. The model is picked per agent, at the point where you define what the agent is for.

Edits are written back to the same markdown files, in the same project and user scopes Claude Code already reads. Operator does not own a copy, so your agents keep working in the terminal with Operator closed.

  • givesThe model decision made where the job is described, not at launch.
  • costsEdits touch real files on disk. Git is your undo.

Landing the work

Parallel agents are only useful if their output can be told apart and merged on purpose. Every task runs sealed off, and comes back as something you read before it counts.

09

Isolated worktrees and fan-out

one worktree per task

Every task runs in its own git worktree, so several agents can work one repository without stepping on each other. Nothing touches your working tree until you say so.

Fan-out is the same idea pushed further: one prompt to N agents at once, each sealed in its own worktree and carrying its own index. Four attempts at a hard bug, and you keep the one that actually fixed it.

  • givesReal parallelism on one repo, with no branch collisions to untangle.
  • costsN worktrees is N checkouts of disk, and N diffs to read.
10

Diff review and usage

local only

Work comes back as a diff you read in place, then commit, merge, or discard without leaving the window. Reviewing is the step that turns an agent's output into your code, so it happens where you already are.

Usage counts tokens per model and where the time went, parsed from the transcripts already on your disk. There are no dollar figures anywhere in Operator: what a token costs depends on your plan, and a confident wrong number is worse than none.

  • givesRead the change and land it in one window.
  • costsTokens, not money. Converting them is left to you.

What it does, and what it leaves alone

Operator hosts Claude Code's own CLI over a pty and reads the transcripts it writes. That single fact decides the shape of everything above, including the parts it deliberately will not do.

BehaviourStatusWhy
Watch a session as it runsdoes Claude Code already writes a transcript. Operator tails it, so there is nothing to install into your sessions.
Type into a running sessiondoes Each session is a real pty, not a re-render of one. You can take the keyboard back at any point.
Run several agents on one repodoes One git worktree per task. Parallel work cannot collide because it is never in the same checkout.
Send one prompt to N agentsdoes Fan-out, each attempt in its own worktree with its own fanIndex. Compare the diffs, keep one.
Stop an agent mid-rundoes The composer's send becomes Stop while it works. That is Claude Code's own interrupt, not a kill: the session survives and hands the turn back.
Read what your agents told each otherdoes The project channel. A dispatch from a non-coordinator lane is held until you approve it, so no lane silently commissions work.
Post to that channel yourselfnot yet The feed and the approval gate ship first. The composer is visibly present and inert rather than hidden, because a dead control found by accident is worse.
Host or proxy the modelleaves alone Operator runs the CLI you already have. Your Claude Code auth, your account, your session.
Send anything to a serverleaves alone Transcripts are read from disk and rendered locally. No upload, no telemetry, no account with us.
Estimate what a session costleaves alone Tokens are measurable; dollars depend on your plan. Operator shows the tokens and stops there.
Push a message into a busy laneleaves alone One submit queue per terminal, with no out-of-band channel into the CLI. A message is queued and read when the current task ends.
It is a control room, not a replacement. Operator does not make Claude Code smarter or take the wheel from you. It makes the work legible while it happens, keeps parallel attempts from ruining each other, and puts the result in front of you as a diff. Everything the agent does is still yours to approve.
